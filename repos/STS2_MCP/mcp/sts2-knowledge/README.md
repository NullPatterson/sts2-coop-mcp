# STS2 Knowledge Base

Reference material for RAG-assisted Slay the Spire 2 play. Scoped intentionally: this is
strategic/judgment content that benefits from retrieval, not a card/relic/potion
database. Exact item effects come from the MCP mod's own wiki tool at inference time —
see `strategy/general-strategy.md` for the note on when to use it instead of this file.

## Layout

```
strategy/general-strategy.md                  # character-agnostic fundamentals — read first
reference/spire-codex-scoring-methodology.md   # how Codex Score / Codex Elo are calculated
reference/status-effects.md                    # buff/debuff/keyword glossary
characters/<name>/overview.md                  # kit summary, starter relic, playstyle
characters/<name>/builds/*.md                  # named build paths, key cards/relics inline
cards_scores.json                              # generated by spire_codex_puller.py
relics_scores.json                             # generated by spire_codex_puller.py
potions_scores.json                            # generated by spire_codex_puller.py
```

Builds per character: Ironclad (Vulnerable, Body Slam, Exhaust), Silent (Sly, Poison,
Shiv), Regent (Stars, Forge), Necrobinder (Souls, Osty, Doom), Defect (Orbs, Claw).

## Exact item lookups: use the wiki tool, not this knowledge base

The MCP mod already exposes a wiki lookup tool with live, current-patch game data. When
a card/relic/potion's exact numbers matter, call that tool rather than trusting a
memorized figure from a build file here — build files describe a card's *role* in an
archetype, not a guaranteed-current stat block. See `strategy/general-strategy.md` for
the full note; this is worth keeping in whatever system prompt drives the agent.

## Build file style

Every build file follows one template, sourced from PCGamesN's character guides (the
most detailed single consistent source found across all 5 characters):

- **Goal** — the archetype's win condition, one line.
- **Early priority cards** — grab these as soon as offered.
- **Consistency cards** — once the core engine is online.
- **Power cards** — mid-to-late game payoffs/finishers.
- **Key relics** — with a one-line reason each.
- **Playstyle notes** — sequencing tips, common mistakes, when to pivot away from this build.

## Community score data (Spire Codex)

`reference/spire-codex-scoring-methodology.md` explains Codex Score (0–100, win-rate
correlation, Bayesian-shrunk) and Codex Elo (cards only, revealed-preference from
reward-screen picks) — read it before surfacing either number to a person, since both
carry real biases (exposure bias, survivorship bias, no ascension/character
normalization — the methodology file spells these out with worked examples).

Generate the three JSON files with `spire_codex_puller.py` (pulls from
spire-codex.com's public REST API + site data; not included in this archive — see the
conversation this knowledge base was built in). Re-run it periodically to keep the
rankings current; Spire Codex's own data refreshes every 30 minutes as new community
runs are submitted.
